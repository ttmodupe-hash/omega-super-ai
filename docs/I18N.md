# Unified i18n Engine Layer (UNIFY-14)

One engine-level i18n owner serving **web/ and cli/ over the same contract**.

## Endpoints (`/v1/i18n`)

| Endpoint | Purpose |
|---|---|
| `GET /languages` | The 22-language registry with **honest coverage stats** per language |
| `GET /negotiate` | RFC 7231 Accept-Language negotiation against the registry |
| `GET /strings?lang=` | Resolved UI catalogue — every key carries `translated` / `fallback` flags |
| `POST /translate` | Dynamic translation with Postgres **translation memory** (TM hit → no LLM; miss → machine translate → cache) |

## The 22-language registry

11 official SA spoken languages (en, zu, xh, af, st, tn, nso, ts, ss, ve, nr)
+ 11 African/global (sw, pt, fr, ar, yo, ig, ha, am, so, lg, sn).
Coverage stats are reported honestly — seeded catalogue keys translated vs
total — so the 22-language claim is never inflated.

## Acceptance flows

**Page (end-to-end):** `static/i18n.html` — browser language →
`/v1/i18n/strings` → rendered catalogue where every string shows a
`translated` or `english fallback` badge, plus a visible fallback notice in
the user's own language when coverage is partial.

**CLI flow:** the CLI sends its configured language as an Accept-Language
header (`LUQI_LANG=tn` → `Accept-Language: tn`) to the same
`/v1/i18n/strings` endpoint. One negotiation path, one string contract —
when cli/ lands in Phase 1 it consumes this contract unchanged; the flow is
proven today by the negotiation + strings tests.

## Fallback law

**English fallback is explicit, never silent.** Per-key `fallback: true`
flags, a `fallback_notice` in the target language, and negotiation responses
that always state the reason (`exact match` / `prefix match` /
`explicit English fallback`). Unsupported `/translate` targets return 400
with the supported list — no silent downgrade.

## Translation memory (Postgres, migration 007)

`i18n_strings (key, locale) → text + provenance (seed|machine|human)`.
Seeded UI catalogue + machine translations cached by content hash. Shared
reference data: RLS forced with an explicit read-for-all policy for
`luqi_app_user` (documented exception to country isolation — a dictionary
is not user data).
